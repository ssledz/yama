The one-sentence version

An agent is an LLM in a loop

...with tools, where the model chooses the next step. Everything else is engineering around that.

def agent(task: String): F[String] =
  def loop(conversation: Vector[Item]): F[String] =
    model.send(conversation).flatMap { reply =>              // one stateless call
      if reply.toolCalls.isEmpty then reply.text.pure      // no tool call: done
      else reply.toolCalls.parTraverse(runTool)          // your code, not the model's
        .flatMap(results => loop(conversation ++ reply.output ++ results))
    }
  loop(Vector(Item.User(task)))                             // the entire state

Who owns the control flow?

Normal app vs agent

 Normal appAgent
Control flowwritten by you, at compile timechosen by the model, at runtime
Determinismsame input → same outputsame input → different paths
Stateyour domain model, DBan ever-growing conversation, Vector[Item]
Interface outtyped API callsnatural-language tool descriptions: the description is the prompt
Errorsexceptions, handled by codefed back as data, so the model recovers
Terminationguaranteed by designneeds a budget: maxRounds, tokens, time
Cost modelCPU per requesttokens × rounds (the transcript is resent every round)
Trust boundaryuser inputuser input and every tool result (prompt injection)

Before you build one

Agent or pipeline?

 Control flow decided byExample
Pipelineyou, at coding timedownload → parse → summarise
Agentthe model, at runtime"fix the failing test" → greps, reads, edits, runs, rereads

If you can enumerate the steps in advance, write the pipeline. "Summarise 10k documents" is a for loop, not an agent.

component · conversation

A conversation is a value

opaque type ToolName = String
opaque type CallId   = String

/** One entry of the conversation. The whole conversation is the agent's memory. */
enum Item:
  case User(text: String)
  case Assistant(text: String)
  case ToolCall(id: CallId, name: ToolName, args: String)  // raw JSON, may be invalid
  case ToolResult(id: CallId, output: Json)            // failures too: {"error": ...}

enum Answer:
  case Final(reply: String, rounds: Int)
  case GaveUp(maxRounds: Int)

The provider JSON is messy; our model of it is a small ADT. Memory is Vector[Item].

component · tool

A tool = schema + handler

trait Tool[F[_]]:
  def name: ToolName
  def description: String      // the description IS the prompt
  def schema: Json             // JSON Schema of the arguments
  def run(args: Json): F[Json]
// component · wget: the schema is derived from the case class, at compile time (Mirror)
final case class WgetArgs(url: String, outputPath: String) derives ToolSchema, Decoder

// {"type":"object","properties":{"url":{"type":"string"},"outputPath":{"type":"string"}},
//  "required":["url","outputPath"],"additionalProperties":false}

The schema constrains shape only. The handler re-validates: outputPath must stay inside the sandbox.

component · tool

Failures are data

def execute(call: Item.ToolCall): F[Item.ToolResult] =
  val output = byName.get(call.name) match
    case None => Tool.error(s"Unknown tool: ${call.name.value}").pure[F]
    case Some(tool) =>
      parse(call.args) match
        case Left(failure) => Tool.error(s"Invalid JSON: ${failure.message}").pure[F]
        case Right(args)   => tool.run(args).handleError(e => Tool.error(e.getMessage))
  output.map(Item.ToolResult(call.id, _))
  • Unknown tool, bad JSON, a failed F: all become {"error": ...} and go back to the model, which recovers. A failure never escapes the loop.
  • Tool calls of one round run in parallel: calls.parTraverse(execute). One word in Cats Effect.

component · agent · Loop.scala

This is all the AI there is

// final class Loop[F[_]: Concurrent: Parallel](chat, tools, ...):
  def run(conversation: Vector[Item], round: Int): F[(Vector[Item], Answer)] =
    if round > maxRounds then (conversation, Answer.GaveUp(maxRounds)).pure[F]
    else
      for
        reply  <- chat.send(instructions, specs, conversation)
        next    = conversation ++ reply.output
        result <-
          if reply.toolCalls.isEmpty then
            (next, Answer.Final(reply.text.getOrElse(""), round)).pure[F]
          else
            reply.toolCalls.parTraverse(execute)
              .flatMap(results => run(next ++ results, round + 1))
      yield result

Recursion through flatMap: stack-safe, no @tailrec. Giving up is a value. Memory is a Ref[F, Vector[Item]], resent every round. 45 lines.

component · mcp-client

A thin wrapper, bridging both ways

trait McpClient[F[_]]:
  def server: String
  def listTools: F[List[McpTool]]
  def callTool(name: String, args: Json): F[Json]     // circe only: no Jackson leaks out

def connect[F[_]: Async: Processes: LoggerFactory](server: McpServer): Resource[F, McpClient[F]]

// Mono → F   (we call the SDK)
Async[F].fromCompletableFuture(Sync[F].delay(mono.toFuture))
// F → Mono   (the SDK calls us back, through a CE Dispatcher)
Mono.fromFuture(() => dispatcher.unsafeToCompletableFuture(fa))
  • Local servers are spawned with the fs2 process API: nested Resources, initialize on acquire, kill on release. No leaked child processes.
  • A supervisor respawns a crashed server (exponential backoff, gives up after 5 quick crashes).

component · mcp-tools · 18 lines

The model can't tell native from MCP

def from[F[_]: Functor](client: McpClient[F]): F[List[Tool[F]]] =
  client.listTools.map(_.map { mcp =>
    Tool[F](
      name        = mcp.name,
      description = mcp.description,
      schema      = mcp.inputSchema,
      origin      = s"mcp:${client.server}"
    )(args => client.callTool(mcp.name, args))
  })

Every remote tool adapted to the same Tool[F] trait. The loop doesn't change.

component · subagent

Agents as tools: orchestrator–worker

def asTool[F[_]: MonadThrow](spec: SubAgentSpec, makeAgent: F[Agent[F]]): Tool[F] =
  Tool[F](
    name        = spec.name,                // "research_agent"
    description = spec.description,         // when to delegate: it's the prompt
    schema      = ToolSchema[SubAgentInput] // SubAgentInput(input: String)
  ) { args =>
    for
      in     <- args.as[SubAgentInput].liftTo[F]
      agent  <- makeAgent               // fresh conversation per call
      answer <- agent.query(in.input)   // the worker's own loop
    yield answer match
      case Answer.Final(text, _) => Json.obj("answer" -> text.asJson)
      case gaveUp: Answer.GaveUp => Tool.error(s"${spec.name}: ${gaveUp.text}")
  }
  • Context isolation: raw search pages stay in the worker; only the condensed answer comes back.
  • The orchestrator can't search, it can only delegate. No new concepts: a loop calling a tool that is itself a loop.

Guardrails

Least privilege at the connection, not in the prompt

budget

Termination is your job

maxRounds per agent: 25 for the orchestrator, 8 for the worker.

Depth = 1: workers never get subagent tools.

sandbox

Two mounts, nothing else

The workspace and a per-run session folder go to files-mcp as FS_ROOTS; wget gets the same list.

tools per agent

Pick servers, not words

agent.mcpServers: ["files"]: Tavily is reachable only through research_agent.

untrusted output

Every tool result is input

A downloaded page saying "ignore previous instructions…" is prompt injection. Mitigation is tool design and the sandbox, not prompt wording.

Wrap-up

Three takeaways

  1. An agent is a loop where the model picks the next step. You own everything else.
  2. Tools are the interface, and the description is the prompt. MCP makes tools reusable, skills make prompts reusable.
  3. Build an agent when the steps can't be enumerated. Otherwise write the pipeline.

Production: cost is transcript × rounds (so caching matters), log every round. Sub-agents, planning, compaction: more prompts and more tools around the same loop.

ToolSchema: derived with Mirror

trait ToolSchema[A]:
  def json: Json
  def optional: Boolean = false

object ToolSchema:
  given ToolSchema[String] = of(tpe("string"))
  given ToolSchema[Int]    = of(tpe("integer"))
  given [A: ToolSchema]: ToolSchema[Option[A]] = ...   // not required

  /** Field names and field types come from the case class Mirror, at compile time. */
  inline def derived[A](using m: Mirror.ProductOf[A]): ToolSchema[A] =
    val names  = constValueTuple[m.MirroredElemLabels].toList.map(_.toString)
    val fields = summonAll[Tuple.Map[m.MirroredElemTypes, ToolSchema]].toList
    objectSchema(names.zip(fields))     // object, properties, required

Versus the hand-written JS schema: the case class is the single source of truth for the schema and the decoder.

Shipping it: one executable file

  • sbt yama-cli/assembly: a fat jar with a sh + cmd launcher in front of the zip, released as yama. chmod +x yama && ./yama, or java -jar yama.
  • First run bootstraps ~/.yama/config.json from the defaults bundled in the jar.

Polylith rules, enforced by sbt

Skills: discovery and trust

  • Discovery: <project>/.yama/skills, <project>/.agents/skills, ~/.yama/skills, ~/.agents/skills, skills.paths, then built-in. Project beats user beats built-in.
  • Trust gate: project skills inject instructions, so they load only with skills.trustProject = true.
  • activate_skill(name): name is a JSON Schema enum of the discovered skills, so the model can't make one up. Returns <skill_content name="…"> with resources listed, not read.
  • read_skill_resource(name, path): read-only, confined to the skill's directory.
  • Lenient validation: rule violations are warnings (/skills), broken YAML skips the skill.
